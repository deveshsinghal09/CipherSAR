# Contribution workflow

The hackathon requires individual work to be traceable. CipherSAR uses a branch-and-pull-request workflow.

## Repository owner

Devesh works from branches such as:

```text
feature/adaptive-agent
feature/compliance-command-center
docs/judge-demo
```

## Collaborator

After accepting the invitation, `AnkitKumar61` should:

1. clone the repository using his own GitHub account;
2. create a branch such as `ankit/<feature-name>`;
3. commit only his own work with his own configured name/email;
4. push the branch;
5. open a pull request describing his contribution;
6. allow the repository owner to review and merge it.

## Integrity rule

Never manufacture commits with another contributor's name or email. Git history is useful evidence only when each contributor actually authors and pushes their work.

## Suggested task split

- Devesh: adaptive planner, API, hybrid detector, integration, release.
- Ankit: evaluation dataset, additional detector tests, accessibility review, or case-management feature.

Record the final division in the pull request descriptions and hackathon submission.
